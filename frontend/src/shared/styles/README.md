# SCSS в UknowApp

## Где менять стили

- `core/` — токены, базовые элементы, общие контролы и оформление тем.
- `components/` — повторно используемые кнопки, чаты и диалоги.
- `features/` — стили конкретных экранов (структура, переписки, пользователи, администрирование, вход).
- `workspace/` — навигация, раскладка, прокрутка, мобильные адаптации.
- `index.scss` — единственная точка подключения. Порядок модулей определяет приоритет при одинаковой специфичности.
- `critical.scss` — отдельная таблица для первого отображения, не входит в `index.scss`.

## Правило редактирования

1. Найти действующее объявление стиля в файле владельца и изменить **его**, а не добавлять ещё один селектор в конец файла.
2. Если свойство задано в нескольких файлах, установить фактический приоритет в браузере; переносить и удалять конфликтующие правила только с регрессионной проверкой.
3. Для адаптивного состояния и тёмной темы редактировать существующий блок того же компонента; общие токены менять только при действительно общей смене дизайна.
4. Избегать `!important`, слишком длинных сжатых строк и файлов с названиями `fixes`, `overrides`, `patches`.
5. Не смешивать структурный перенос CSS с визуальными изменениями в одном коммите.

## Проверки

```sh
cd frontend
npm run check:scss
npm run audit:css
npm run build
node scripts/verify-scss-equivalence.mjs <sha-базового-коммита>
```

`check:scss` проверяет структуру, ссылки `@use`, отсутствие `!important` и минифицированных строк. `audit:css` ищет повторяющиеся правила и неиспользуемые переменные. `verify-scss-equivalence` сравнивает **скомпилированный CSS побайтно** с указанным коммитом; используйте его для переносов, сохраняющих порядок и состав правил. При объединении селекторов сравнивайте страницы и состояния в браузере с базовой сборкой.

Если ожидается изменение оформления, побайтовая эквивалентность не подходит: сравните реальные страницы в браузере на узком и широком экране, в светлой и тёмной теме, включая состояния hover, focus, touch, свёрнутые списки и модальные окна. Без такой проверки массовое удаление каскадных правил запрещено.
