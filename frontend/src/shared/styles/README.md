# Стили UknowApp

Стили написаны на SCSS и разделены по назначению. Общие правила не нужно дублировать в отдельных экранах.

## Где менять стили

| Папка или файл | Назначение |
| --- | --- |
| `core/` | Токены, темы, базовые элементы и контролы |
| `components/` | Общие кнопки, чаты и диалоги |
| `features/` | Стили отдельных экранов |
| `workspace/` | Навигация, раскладка, прокрутка и адаптивность |
| `index.scss` | Единая точка подключения SCSS; порядок импортов влияет на каскад |
| `critical.css` | Стили первого кадра, подключаемые через HTML |

## Как вносить изменения

1. Найдите существующее правило в файле его компонента и измените его вместо добавления нового селектора в конец файла.
2. При дублировании сначала проверьте приоритет правил в браузере. Переносите или удаляйте их только после регрессионной проверки.
3. Адаптивность и тёмную тему меняйте в существующих блоках компонента. Общие токены — только для общих изменений дизайна.
4. Избегайте `!important`, длинных сжатых строк и файлов `fixes`, `overrides`, `patches`.
5. Не смешивайте структурный перенос CSS с визуальными изменениями в одном коммите.

## Проверки

Из папки проекта:

```bash
cd frontend
npm run check:scss
npm run audit:css
npm run build
```

| Команда | Что проверяет |
| --- | --- |
| `check:scss` | Структуру, ссылки `@use`, отсутствие `!important` и минифицированных строк |
| `audit:css` | Повторяющиеся правила и неиспользуемые переменные |
| `build` | Сборку приложения |

При переносе правил без изменения дизайна можно сравнить собранный CSS побайтно с базовым коммитом:

```bash
node scripts/verify-scss-equivalence.mjs <sha-базового-коммита>
```

При объединении селекторов или изменении дизайна сравните реальные страницы с базовой сборкой в браузере:

- Узкие и широкие экраны.
- Светлая и тёмная темы.
- Состояния hover, focus, touch, свёрнутые списки и модальные окна.

Побайтовое сравнение не подходит для намеренных визуальных изменений. Не удаляйте массово правила каскада без проверки интерфейса.
