# Web Push: несколько устройств (test)

У каждого браузера/PWA собственная подписка (endpoint) и браузерная сессия. Повторное открытие приложения, вход, возвращение на передний план и восстановление сети синхронизируют уже разрешённую подписку с Core. Ручное отключение уведомлений хранится локально и не влияет на другие устройства. При входе система по-прежнему может запросить разрешение браузера, если пользователь ранее его не отключил.

При отсутствии строки в БД действующая локальная подписка регистрируется повторно. При 404/410 от push-провайдера Core сохраняет отметку expired и исключает её из рассылки. При следующей синхронизации такой endpoint получает 410, браузер создаёт новую подписку. Известная смена VAPID-ключа и локальный срок действия также приводят к обновлению. Устройства, которые никогда не открывают приложение, не могут автоматически восстановить подписку. На iOS требуется установленная PWA и разрешение уведомлений.

Рассылка выполняется вне потока запроса в общем пуле до 10 сетевых обработчиков. Ошибки одного endpoint не прерывают остальные. Статусы сохраняются отдельно, без раскрытия адресов подписок и ключей. Provider accepted означает принятие Web Push сервисом, а не гарантию показа на экране. Существующая проверка доступа в Service Worker и подавление уведомления для открытого активного диалога сохраняются; они относятся только к этому устройству. Push не зависит от NATS и коннекторов.

GET /api/admin/push/diagnostics — только администратор. Поля: registered, eligible, admin_devices, admin_eligible, devices (id, роль, user_id, провайдер, дата регистрации/синхронизации, последняя попытка/успех, state, http_status, session_active). Legacy-подписки без связи с сессией имеют session_active=null до первого открытия приложения. Устаревшие и привязанные к недействующим сессиям строки не считаются доступными для доставки. Диагностика не содержит endpoint, auth, p256dh или session_hash.

При выходе браузер удаляет только свой endpoint и отписывается локально; серверный logout дополнительно удаляет подписки текущей сессии. При повторном входе прежние записи этой сессии становятся неактивными до синхронизации, чтобы не терять отметку expired.

Реальную доставку проверьте на двух и более телефонах: откройте UknowApp на каждом, разрешите уведомления, сверните все приложения и отправьте сообщение от ученика/преподавателя. В диагностике должно быть соответствующее число admin_eligible. Выход с одного телефона не меняет подписки других. Если provider accepted, но уведомление не показано, проверьте разрешения ОС, Focus/Не беспокоить, активный диалог и срок сессии. Тесты используют реальные API регистрации и имитацию push-провайдера, не физические телефоны.
