# База данных и автоматические миграции (test)

Core поддерживает SQLite по умолчанию и PostgreSQL. При каждом запуске, в том числе после восстановления, `initialize_database()` автоматически обновляет схему. Ручной запуск Alembic и промежуточных версий не требуется для проверенных схем.

## Выбор базы

| | SQLite | PostgreSQL |
| --- | --- | --- |
| Настройка | Пустой `DATABASE_URL` | URL через `psycopg` |
| Docker | Том `app_data` | Профиль `postgres`, том `postgres_data` |
| Резервные копии | Полный ZIP из админ-панели | `pg_dump`, `pg_restore` и отдельный архив файлов |

> [!IMPORTANT]
> Смена `DATABASE_URL` не переносит данные. Перенос между СУБД не автоматизирован.

## Новый сервер с PostgreSQL

Только для пустой установки. В `.env` задайте:

```dotenv
COMPOSE_PROFILES=postgres
POSTGRES_DB=uknowapp
POSTGRES_USER=uknowapp
POSTGRES_PASSWORD=YOUR_PASSWORD
DATABASE_URL=postgresql+psycopg://uknowapp:YOUR_PASSWORD@postgres:5432/uknowapp # pragma: allowlist secret
```

Замените пароль; специальные символы в URL должны быть URL-кодированы. Для коннекторов добавьте нужные профили, не удаляя `postgres`.

```bash
docker compose --profile postgres up -d postgres
docker compose build core
docker compose up -d --build
```

## Обновление существующей установки

1. Сделайте проверенную резервную копию базы, медиа, VAPID-ключей и постоянных томов коннекторов/брокера. Подробнее — [согласованное хранение](runtime-storage.md).
2. Проверьте штатное обновление на копии старой базы.
3. Обновите ветку `test` и пересоберите сервисы командами из [руководства по ботам](bots-gateway.md).
4. Проверьте health, логи, пользователей, переписки, привязки, вложения и уведомления.

Не удаляйте тома и не запускайте две версии Core на одной базе.

## Как работают миграции

- Выполняются до HTTP API, NATS и коннекторов.
- SQLite использует `BEGIN IMMEDIATE`, PostgreSQL — транзакционную advisory lock.
- Изменения схемы и отметки `schema_migrations` сохраняются в одной транзакции; при ошибке откатываются.
- Повторный запуск пропускает выполненные шаги.
- В конце проверяются актуальные таблицы и колонки. При неизвестной или неполной схеме запуск останавливается; штатный restore возвращает исходные данные.

Проверка структуры не гарантирует корректности произвольной повреждённой или сторонней базы.

## Правила разработки

Единственный реестр — `MIGRATIONS` в `backend/app/migrations/__init__.py` и его помощники. Каждому изменению схемы нужен уникальный ID; старые ID не меняются и не удаляются.

Alembic остаётся библиотекой DDL, отдельного реестра ревизий нет. Старая таблица `alembic_version` сохраняется, но не используется.

Сначала переносите бизнес-данные и идентификаторы, затем удаляйте устаревшие структуры. Не заменяйте рабочую БД пустой и не угадывайте значения неизвестных колонок. Известные исключения — снятые интерактивные доски, старое техническое состояние панели бота, истёкшие сессии и коды.

> [!WARNING]
> После удаления колонок откат на старый код требует восстановления резервной копии.
> До запуска миграций зафиксируйте SHA старого кода и сохраните согласованный снимок Main DB, Runtime, медиа, NATS, коннектора и защищённого `.env`. Проверьте восстановление на отдельной установке.
> При неудаче остановите Core и коннекторы, восстановите весь согласованный снимок, затем запустите прежнюю ревизию. Не запускайте старый код поверх мигрированной базы.

## Регрессионные проверки

Исторические схемы в `backend/tests/fixtures/schema_*.py` используются только в тестах. Проверяются переходы со встроенного Telegram, WebSocket Gateway, ранней NATS-доставки и версии до многодевайсного Push.

Тесты охватывают пользователей и пароли, назначения, обычные и личные диалоги, вложения, прочтения, внешние ID, привязки, очереди и подписки, повторный запуск и SQLite rollback при искусственной ошибке. Database compatibility CI проверяет SQLite и PostgreSQL; реальные архивы школы не используются.

## Восстановление

SQLite поддерживает полный ZIP и отдельный импорт базы при наличии медиа. После установки старой БД выполняются те же миграции; при ошибке штатный restore возвращает предыдущие данные.

PostgreSQL не поддерживает SQLite ZIP и веб-импорт (HTTP 501). Храните SQL-дамп, Runtime, медиа, VAPID и состояние коннекторов/брокера согласованно. См. [Bots Gateway](bots-gateway.md) и [Main DB / Runtime DB](runtime-storage.md).
