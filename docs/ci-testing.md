# Проверки и тесты UknowApp

Аудит на 23 ноября 2026 года, по текущему коду `main`.

## Что выполняется

| Задача | Покрытие | Почему оставлена |
| --- | --- | --- |
| Frontend build и SCSS architecture | Сборка Vite/Solid, целостность SCSS-модулей | Проверяет реальные компоненты и стили |
| Frontend unit (`npm test`) | Сообщения, прочтения, realtime/SSE, даты, CSP, первый рендер, PWA-иконки | Все 7 существующих unit/contract-файлов включены в npm-script |
| Browser (`npm run test:browser`) | Аутентификация/доступ к рабочему пространству, UI диалогов, realtime, push-обновления | Оба текущих browser-файла (включая подробный интеграционный сценарий) |
| CSS lint / audit | Правила общего SCSS и кандидаты на неиспользуемые селекторы | Позволяет менять дизайн без обязательной идентичности прошлому CSS |
| Backend lint, security | Ruff (включая BLE001, SIM115, B008), Vulture, Bandit, detect-secrets | Сохранены проверки безопасности и качества |

| PWA icon workflow | Перегенерация PNG при изменении исходной иконки/скрипта | Отдельный workflow, запускается только для подходящих файлов |

Тест `backend/tests/test_board_removal.py` не устарел: он проверяет, что удалённые API и таблицы досок не появились снова. Тесты backup/restore и прав доступа сохранены, но разделены между независимыми задачами, чтобы не запускать одни и те же тесты дважды.

## Что ускорено

- В `frontend-browser` используется официальный Playwright Chromium Headless Shell с кэшем GitHub Actions, а не медленно запускающийся системный Google Chrome. При пустом кэше скачивается только headless shell; при повторных прогонах браузер берётся из кэша. Тесты также поддерживают `CHROMIUM_PATH` при локальной разработке.
- Браузерные сценарии работают на заранее собранном `dist` через `vite preview` вместо dev-сервера; проверяют тот же интерфейс с production-ассетами. Скачивание браузера при каждом прогоне и установка apt-зависимостей не нужны.
- Проверки Ruff объединены в один проход с `--extend-select`, без отключения дополнительных правил.
- Удалён второй самостоятельный импорт `app.main` в CI: его выполняют существующие pytest-тесты.
- Проверка абсолютной идентичности CSS удалена полностью. При изменении дизайна CI проверяет сборку, SCSS-архитектуру, Stylelint и аудит селекторов, но не сравнивает CSS с предыдущим коммитом.
- Новый push/PR в той же ветке отменяет устаревший прогон, но не прерывает проверки других веток.

## Дополнительная параллелизация

- Проверки браузера вынесены в отдельную задачу `frontend-browser`, которая выполняется одновременно со сборкой, unit-тестами и Stylelint в `frontend`.
- Тесты backend ускорены кэшем четырёх повторяющихся PBKDF2-хешей **только** в изолированных test fixtures; production-хеширование и проверка пароля не менялись.
- Для `backend` и `backup-function` использован `uv pip install --system` с кэшем; Python 3.11 и все исходные проверки сохранены. Идентичные PBKDF2-хеши кэшируются исключительно в тестовой фикстуре.
- Успешный прогон `a278a3e` после оптимизаций: полный CI — 36 с, `frontend` — 18 с, `frontend-browser` — 32 с (с восстановлением браузерного кэша), `backend` — 27 с, `backup-function` — 28 с. Сами два браузерных теста после замены браузера — приблизительно 5,5 с и 1,2 с против 17,5 с и 12,3 с ранее. Показатель полного CI варьируется от запуска к запуску из-за очереди и загрузки GitHub runners; снижать покрытие ради отдельного удачного замера нельзя. Параллельные jobs потребляют больше суммарных runner-минут.

## Оптимизации загрузки, отклика и сборки (23 ноября 2026)

- `workspaceRegistry.js` динамически загружает кабинеты `admin`, `teacher` и `student` только после проверки роли сервером. Страницу чатов в кабинетах администратора и учителя загружаем только при переходе в диалоги.
- На странице входа браузер больше не загружает сразу всю логику рабочих кабинетов. В сборке до разделения начальный JavaScript был одним файлом `144.36 kB` (`49.03 kB gzip`). После разделения стартовые JS-файлы — `47.18 kB` и `60.85 kB` (`16.17+23.39 = 39.56 kB gzip`), около 19% меньше по gzip; остальной код загружается по мере необходимости. CSS пока общий (`20.47 kB gzip`).
- Успешный вход больше не ждёт необязательного запроса разрешения Push/регистрации подписки: кабинет открывается сразу после подтверждения входа backend. Повторная подписка при параллельной инициализации исключена. Проверяется регрессионным тестом с намеренно задержанной подпиской.
- Caddy кэширует только хешированные `/assets/*` с `Cache-Control: public, max-age=31536000, immutable`. Отсутствующие ассеты дают HTTP 404, а не устаревшую SPA-страницу. `index.html`, API и service worker имеют прежнюю политику кэширования.
- Успешный полный CI после изменений — **29 с** (проверки `frontend` — 11 с, `frontend-browser` — 25 с, `backend` — 26 с, `backup-function` — 18 с), все проверки завершились успешно. До изменений загрузки приложения зафиксирован успешный прогон 36 с. Цифры зависят от загрузки GitHub runners.
- Сама компиляция Vite остаётся быстрой: пример до разделения на чанки — `522 ms`, после — `835 ms`. Разделение на чанки ускоряет загрузку приложения, **не** саму команду `vite build`; дополнительных рискованных изменений компилятора ради долей секунды не внесено.

## Запуск локально

```bash
cd frontend
npm ci
npm test
npm run build
npm install --no-save playwright@1.56.1
npm run test:browser # нужен установленный браузер Playwright или CHROMIUM_PATH
```

```bash
cd backend
python -m pip install -r requirements.txt
python -m pip install ruff vulture bandit detect-secrets pytest httpx
ruff check app --extend-select BLE001,SIM115,B008
python -m pytest -q tests
```

В CI `backup-function` запускает `python -m pytest -q tests/test_admin_data_backup.py tests/test_restore_startup.py`. Прежний Compose/browser-тест переноса удалён: он проверял резервную копию ценой сборки двух копий приложения. Остальные backend-тесты запускаются в `backend` с исключением указанных двух файлов. Все операции выполняются с изолированными тестовыми данными — действующая база школы не затрагивается.
