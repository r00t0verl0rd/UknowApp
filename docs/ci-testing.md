# Тестирование UknowApp

Тесты проверяют доступность функций, безопасность, целостность данных и совместимость протоколов, а не буквальное совпадение CSS/JS с прежней реализацией.

## Уровни CI

| Уровень | Когда | Проверки |
| --- | --- | --- |
| Project checks | Каждый push в main/test и PR | Frontend-сборка и unit-тесты, Ruff, Vulture, Bandit, detect-secrets, backend-тесты, экспорт и восстановление backup |
| Browser integration | Изменения frontend, backend API или Compose; любой PR | Реальные действия в Chromium, права, диалоги, SSE, история, доступность кнопок, адаптивность |
| Database compatibility | Изменения backend, Compose или workflow; любой PR | Миграции и совместимость SQLite/PostgreSQL, статистика и исторические схемы |
| NATS Gateway checks | Изменения backend, коннекторов или инфраструктуры; любой PR | Реальный NATS RPC/JetStream, восстановление доставки, тесты коннекторов, валидация Compose |
| Release validation | PR — полный набор отдельных workflows; вручную — единый workflow | Все перечисленные проверки, сборка Docker-образов и нагрузка 100 000 сообщений |

Перед развёртыванием проверяйте одну и ту же ревизию. Запустите **Release validation** через Actions → Run workflow → test, если кнопка доступна. GitHub может не показывать ручной запуск нового workflow до его появления в default branch; альтернативно отправьте отдельный тег вида `release-check-<sha>`, указывающий на проверяемую ревизию. Workflow не развёртывает приложение и не изменяет сервер. Не считайте пропущенные по фильтрам задания результатом полной проверки.

## Правила поддержки тестов

- Проверяйте пользовательский результат и инварианты: права доступа, доставку, отсутствие дубликатов, прочтения, восстановление и сохранность данных.
- Не закрепляйте буквальное представление полностью прозрачного цвета, точную косметическую геометрию или конкретный CSS-селектор, если это не функциональный контракт.
- Мобильный вход и доступность диалогов с открытой клавиатурой проверяет `tests/mobile-interactions.browser.test.js`. Сценарий realtime проверяет доставку событий, счётчики и восстановление пропущенных обновлений.
- Исторические миграции сохраняются до официального прекращения поддержки соответствующих схем.
- Backend и backup тестируются один раз в обычном CI; тесты СУБД принадлежат Database compatibility. Gateway не повторяет весь frontend/backend.
- Быстрая проверка счётчиков использует 2 000 сообщений; релизная — 100 000 через `UKNOWAPP_FULL_PERFORMANCE=1`. Отдельный benchmark и сборка образов запускаются в полной проверке.
- Pytest выводит длительность самых медленных тестов. Результаты нового CI сравниваются по журналам, не по предполагаемому времени.

## Как запустить тесты локально

### Frontend

Из корня проекта:

```bash
cd frontend
npm ci
npm run build
npm test
```

Для браузерных тестов:

```bash
npm install --no-save playwright@1.56.1
npx playwright install --only-shell chromium
npm run test:browser
```

Можно использовать уже установленный совместимый браузер через `CHROMIUM_PATH`. Тесты проверяют собранный `dist` через `vite preview`.

### Backend

Из корня проекта, в активном Python-окружении:

```bash
cd backend
python -m pip install -r requirements.txt
python -m pip install ruff vulture bandit detect-secrets pytest httpx httpx2
ruff check app --extend-select BLE001,SIM115,B008
python -m pytest -q tests
```

Только резервное копирование и восстановление:

```bash
python -m pytest -q tests/test_admin_data_backup.py tests/test_restore_startup.py
```

### Стили

Для работы с дизайном см. [правила SCSS](../frontend/src/shared/styles/README.md). CI проверяет сборку и архитектуру стилей, но не требует побайтового совпадения CSS с предыдущим коммитом.

### Gateway и база данных

Дополнительные проверки находятся в [bots-gateway.yml](../.github/workflows/bots-gateway.yml) и [database-ci.yml](../.github/workflows/database-ci.yml). См. [Bots Gateway](bots-gateway.md), [миграции](database-migrations.md) и [производительность Core](core-performance.md).

## Как ускорены проверки

- Быстрые и интеграционные задания выполняются параллельно; Python-зависимости кэшируются через uv.
- Chromium Headless Shell кэшируется; браузерные тесты используют production-сборку.
- Полный Gateway больше не повторяет unit-тесты frontend и backend.
- Полный тест миграций, нагрузка и сборка образов остаются обязательными перед релизом.
- Локальные исключения Bandit B608 относятся к статическим SQL-триггерам и фиксированным именам таблиц в тестах; произвольные ссылки в генераторе SQL отклоняются регрессионным тестом.
- Для Starlette установлен httpx2, httpx сохранён для прямых HTTP-тестов. Предупреждение о слабом пароле в production не отключено.

## Оптимизации приложения

Изменения от 23 ноября 2026 года:

| Что изменилось | Результат |
| --- | --- |
| Динамическая загрузка кабинетов через `workspaceRegistry.js` | Код кабинетов загружается после проверки роли, чаты — при переходе к ним |
| Разделение JavaScript | Меньше кода при первом открытии сайта |
| Push-подписка после входа | Кабинет открывается без ожидания необязательной подписки; параллельная инициализация не дублирует подписку |
| Кэширование Caddy | Хешированные `/assets/*` кэшируются на год; отсутствующие файлы возвращают 404 |

Политика кэширования HTML, API и service worker сохранена. Задержанная push-подписка проверяется регрессионным тестом.

## История замеров

Замеры зафиксированы 23 ноября 2026 года в прежней архитектуре, до отдельного Gateway и database CI. Это исторические результаты, не замеры текущей ветки `test`.

| Задача | До оптимизаций (`ec1484f`) | После оптимизации CI (`a278a3e`) | После изменений загрузки |
| --- | ---: | ---: | ---: |
| Полный CI | — | 36 с | 29 с |
| Frontend | 226 с | 18 с | 11 с |
| Browser | — | 32 с | 25 с |
| Backend | 50 с | 27 с | 26 с |
| Backup | — | 28 с | 18 с |

Ранее отдельный migration job занимал 141 с; его заменил backup-function, поэтому прямое сравнение некорректно. Из 226 с первоначального frontend 193 с занимала установка Chromium, в migration — 46 с. После замены браузера два сценария занимали примерно 5,5 и 1,2 с вместо 17,5 и 12,3 с.

| Метрика сборки | До разделения | После |
| --- | --- | --- |
| Стартовый JS | 144,36 КБ | 47,18 + 60,85 КБ |
| Стартовый JS (gzip) | 49,03 КБ | 16,17 + 23,39 КБ |
| CSS (gzip) | — | 20,47 КБ |
| Vite build | 522 мс | 835 мс |

Стартовый JS уменьшился примерно на 19% по gzip. Разделение кода ускоряет загрузку страницы, а не саму компиляцию Vite. Время CI зависит от очередей, кэша и загрузки runners; параллельные задачи могут потреблять больше суммарных runner-минут.
