# Устройство UknowApp

**UknowApp** — основное приложение онлайн-школы UknowSchool. Сейчас его центральная функция — диалоги внутри платформы. Веб-интерфейс SolidJS 2.0.3, API FastAPI и база SQLite работают независимо от внешних мессенджеров. Боты подключаются как дополнительные модули: сейчас реализован Telegram, архитектура предусматривает другие мессенджеры. Планируется добавление видеосвязи.

**Источник данных — UknowApp**, а мессенджеры служат дополнительными каналами общения.

## Серверная часть

Основной код — `backend/app/`:

| Путь | Назначение |
| --- | --- |
| `main.py`, `api.py` | Запуск приложения, подключение HTTP-маршрутов и фонового Telegram polling |
| `core/` | Настройки, подключение к базе, функции безопасности |
| `models.py`, `migrations/` | Таблицы SQLAlchemy и обновление схемы при запуске |
| `modules/auth/`, `modules/users/` | Вход, сессии и учётные записи |
| `modules/assignments/`, `modules/conversations/` | Назначения и переписки |
| `modules/communication/`, `modules/messaging/` | Общая обработка и доставка сообщений |
| `modules/telegram/` | Подключаемый Telegram-бот и его обработчики |
| `modules/administration/` | Управление школой и резервные копии |
| `modules/notifications/` | Web Push-уведомления |
| `infrastructure/storage/` | Сохранение вложений |
| `event_hub.py` | События для обновления веб-панели |

## Веб-интерфейс

Код находится в `frontend/src/`:

- `app/` — вход в систему и запуск интерфейса.
- `workspaces/` — отдельные кабинеты для текущих ролей: администратора, преподавателя и ученика; точка регистрации кабинетов — `workspaceRegistry.js`.
- `features/` — пользователи, структура, переписки, администрирование и уведомления.
- `shared/components/` и `shared/state/` — общие компоненты и логика.
- `shared/services/` — запросы API и единое подключение SSE для обновлений.
- `shared/styles/` — темы и стили. Точка входа — `index.scss`; порядок импортов имеет значение.

Вкладка **«Доски»** сохранена в административном меню как пустая страница.

Интерфейс получает краткие обновления всех диалогов через SSE, а полную историю загружает для открытого чата.

**Кнопки с одной иконкой:** используйте общий `frontend/src/shared/components/IconButton.jsx`. Оформление находится в `frontend/src/shared/styles/icon-actions.scss`: квадрат, скруглённая рамка, единые состояния в обеих темах. Для опасных действий — `tone="danger"`, для тесных мест — `size="compact"`. Не создавайте отдельные стили для карандашей, стрелок и крестиков в каждом разделе.

## Расширение ролей

Сейчас реализованы три роли, но их количество может расти. Новая роль требует согласованных изменений в проверках прав backend, назначении доступных данных и действий, входе и сессиях, а также регистрации собственного кабинета в `frontend/src/workspaces/workspaceRegistry.js`. Проверки доступа должны выполняться **на сервере**, независимо от скрытия или отображения элементов интерфейса. Новые роли не начинают работать автоматически только от добавления пункта меню.

## Развёртывание и данные

`docker-compose.yml` запускает backend и frontend (Caddy). Собственный Telegram Bot API — отдельный необязательный сервис с профилем `telegram`.

Данные SQLite, вложения и ключ Web Push сохраняются в томе `app_data`. Тома `caddy_data` и `caddy_config` нужны Caddy для HTTPS. Миграции запускаются при старте backend.

**Правила сопровождения:** основная платформа должна работать без мессенджеров; боты не должны владеть общей логикой диалогов; новые учебные модули и роли подключаются независимо. Для Telegram — один процесс polling на токен. Секреты не хранить в Git, тома Docker не удалять при обновлениях.
