# UknowApp

UknowApp — приложение онлайн-школы **UknowSchool**, в котором администраторы, преподаватели и ученики могут общаться и обмениваться файлами. Приложением можно пользоваться прямо в браузере или подключить Telegram-бота.

Что уже есть:

- Личные кабинеты администратора, преподавателя и ученика.
- Чаты, фотографии, видео, документы и голосовые сообщения.
- Уведомления о новых сообщениях.
- Управление пользователями и резервными копиями.

В будущем планируется добавить видеосвязь. Вкладка «Доски» пока не используется.

## Как установить UknowApp на сервер

Даже если вы раньше не разворачивали приложения, начните с этой инструкции. Будем двигаться по шагам: подготовим сервер, скачаем проект, настроим его и откроем сайт.

Это инструкция для **нового сервера Debian 13 (trixie), x86_64/amd64, с systemd**. Мы установим приложение на один VPS, с базой SQLite и обычным Telegram API. Бот необязателен.

> Если приложение уже установлено, переходите сразу к разделу [Как обновить приложение](#как-обновить-приложение).

### Что понадобится

- VPS — виртуальный сервер с публичным IPv4-адресом и доступом по SSH от пользователя `root`.
- Домен (адрес вашего сайта) и доступ к его DNS-настройкам.
- Пароль, который вы придумаете для администратора приложения.
- Токен Telegram-бота, если хотите подключить Telegram.

Команды ниже копируйте в терминал по одному блоку, в указанном порядке. Если команда закончилась ошибкой, сначала исправьте её и только потом продолжайте.

### Шаг 1. Подготовьте домен и подключитесь к серверу

В панели управления доменом создайте две A-записи: для `uknowschool.ru` и `www.uknowschool.ru`, обе с публичным IPv4 вашего сервера. Если используете собственный домен, укажите его и его вариант с `www`.

Если есть AAAA-записи (IPv6), они должны вести на этот же сервер по рабочему IPv6. Ненужные AAAA-записи удалите.

В настройках сетевого экрана (firewall) у провайдера и на сервере разрешите входящие TCP-порты 22 (SSH), 80 (HTTP) и 443 (HTTPS). UDP 443 нужен только для HTTP/3. Внутренние порты приложения, базы и Telegram API открывать не нужно.

Откройте терминал на своём компьютере и подключитесь к VPS:

```bash
ssh root@VPS_IP
```

Вместо `VPS_IP` подставьте реальный IP-адрес сервера. При первом подключении сверяйте отпечаток SSH-ключа с данными провайдера. После подключения следующие команды выполняются уже на сервере.

### Шаг 2. Установите Docker

На сервере нужны Docker Engine, Docker Compose и Buildx.

Если Docker ещё не установлен, установите его по [официальной инструкции для Debian](https://docs.docker.com/engine/install/debian/#install-using-the-apt-repository). Используйте комплект из официального APT-репозитория Docker. Если Docker уже работает, переустанавливать его не нужно.

Установите инструменты, которые понадобятся дальше:

```bash
apt-get update
apt-get install -y git nano curl
systemctl enable --now docker
```

Проверьте, что всё работает:

```bash
docker --version
docker compose version
docker buildx version
docker run --rm hello-world
```

Если команды показывают версии, а тестовый контейнер выводит `Hello from Docker!`, переходите к следующему шагу.

### Шаг 3. Создайте пользователя для приложения

Создадим отдельного пользователя `uknow`, от имени которого будем работать с проектом:

```bash
id uknow >/dev/null 2>&1 || useradd -m -s /bin/bash uknow
usermod -aG docker uknow
```

Теперь переключитесь на него отдельной командой:

```bash
su - uknow
```

Убедитесь, что всё получилось:

```bash
whoami
docker compose version
docker buildx version
docker ps
```

Первая команда должна показать `uknow`. Пустой список контейнеров — нормально. **Все дальнейшие команды выполняйте от пользователя `uknow`**, а не от root.

Группа `docker` даёт права, сопоставимые с root. Не добавляйте в неё учеников или других недоверенных пользователей.

### Шаг 4. Скачайте проект

```bash
cd ~
git clone --branch main https://github.com/r00t0verl0rd/UknowApp.git
cd ~/UknowApp
```

Теперь файлы приложения находятся в папке `/home/uknow/UknowApp`.

### Шаг 5. Настройте приложение

Создайте файл настроек `.env` из готового шаблона и откройте его:

```bash
umask 077
cp -n .env.example .env
chmod 600 .env
nano .env
```

Не нужно разбираться во всех настройках. Для первого запуска найдите в файле следующие строки и измените их значения. Остальные строки оставьте как есть.

| Настройка | Что указать |
| --- | --- |
| `DOMAIN` | `uknowschool.ru` или ваш домен без `https://` |
| `ADMIN_USERNAME` | Логин администратора, например `admin` |
| `ADMIN_PASSWORD` | Свой уникальный пароль, минимум 16 символов |
| `TELEGRAM_BOT_ENABLED` | `false` для запуска без бота, `true` для работы с ботом |
| `TELEGRAM_BOT_TOKEN` | Токен от [@BotFather](https://t.me/BotFather), либо оставьте пустым, если бот выключен |
| `VAPID_SUBJECT` | Ваш контактный email в формате `mailto:you@example.com` |

Для обычной установки убедитесь, что остальные значения остались такими:

```ini
TELEGRAM_API_MODE=cloud
COMPOSE_PROFILES=
DATABASE_URL=
SEED_DEMO_DATA=false
ALLOWED_ORIGINS=
```

Пустой `DATABASE_URL` означает, что приложение само создаст базу SQLite. В cloud-режиме Telegram API ID и Hash не нужны.

Чтобы сохранить файл в редакторе nano, нажмите **Ctrl+O**, затем **Enter**. Для выхода нажмите **Ctrl+X**.

> В `.env` хранятся секретные данные. Не отправляйте этот файл другим людям и не добавляйте его в Git. При обновлении никогда не заменяйте рабочий `.env` шаблоном.

**Если у вас другой домен**, до сборки откройте ещё один файл:

```bash
nano frontend/Caddyfile
```

Найдите строку `uknowschool.ru, www.uknowschool.ru {` и замените оба имени на свои. Если вариант с `www` вам не нужен, оставьте только основной домен и открывающую фигурную скобку. Сохраните файл тем же способом. Изменить только `DOMAIN` в `.env` недостаточно.

### Шаг 6. Запустите приложение

```bash
cd ~/UknowApp
docker compose config --quiet
docker compose up -d --build
```

Docker скачает необходимые компоненты, соберёт приложение и запустит его в фоне. При первом запуске сборка может занять несколько минут — дождитесь окончания команды.

Проверьте состояние:

```bash
docker compose ps
```

Должны быть запущены два основных сервиса: `backend` (сервер приложения) и `frontend` (сайт). После проверки состояния оба должны стать `healthy`. Если пока написано `starting`, повторите команду немного позже.

### Шаг 7. Откройте сайт

Откройте в браузере **https://uknowschool.ru** (или свой домен). HTTPS-сертификат Caddy выпустит автоматически, если DNS и порты настроены правильно.

Введите логин и пароль администратора из `.env`. В панели администратора можно создавать учётные записи преподавателей и учеников, выдавать им логины и коды доступа. Для Telegram есть отдельные коды привязки.

Проверьте также, что сервер отвечает:

```bash
curl -fsS https://uknowschool.ru/api/health
```

Для своего домена замените адрес. Команда должна вернуть ответ без ошибки.

Если подключили Telegram, проверьте отправку сообщений и вложений в обе стороны. В логах backend должны появиться `TELEGRAM_CONNECTED` и `TELEGRAM_POLLING_STARTED`:

```bash
docker compose logs --tail=40 backend
```

Готово! Приложение работает в фоне и продолжит работать после закрытия SSH-сессии. После перезагрузки VPS контейнеры запустятся автоматически.

## Как обновить приложение

Эта инструкция для уже установленного приложения. Повторно устанавливать Docker, создавать пользователя или копировать `.env.example` не нужно.

**Перед обновлением** скачайте полную резервную копию из панели администратора и убедитесь, что её можно восстановить (для SQLite — желательно на тестовой установке). Для PostgreSQL нужен отдельный бэкап базы и файлов.

Подключитесь к серверу, переключитесь на пользователя `uknow` (если вы вошли как root), затем выполните:

```bash
cd ~/UknowApp
git pull --ff-only origin main
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail=40 backend
```

Проверьте, что сайт открывается и вход работает. Во время обновления возможен короткий перерыв.

Если вы меняли `frontend/Caddyfile` под свой домен и Git сообщает о конфликте, не сбрасывайте изменения принудительно — сначала сохраните свою конфигурацию и разберитесь с конфликтом.

Ваши настройки и данные сохраняются в постоянных томах Docker и файле `.env`. Новые параметры из `.env.example` при необходимости добавляйте вручную.

**Не выполняйте** `docker compose down -v`, `docker volume prune` и не удаляйте каталог данных Docker: это может привести к потере базы, файлов и ключей.

## Полезные команды

Выполняйте из папки `~/UknowApp` от пользователя `uknow`.

| Что хотите сделать | Команда |
| --- | --- |
| Посмотреть состояние приложения | `docker compose ps` |
| Посмотреть последние сообщения сервера | `docker compose logs --tail=100 backend` |
| Посмотреть последние сообщения сайта | `docker compose logs --tail=100 frontend` |
| Перезапустить приложение | `docker compose restart` |
| Остановить приложение (без удаления данных) | `docker compose stop` |
| Снова запустить приложение | `docker compose up -d` |

После изменения `.env` используйте `docker compose up -d`, чтобы настройки попали в контейнеры. Обычный `restart` не перечитывает переменные окружения.

## Если что-то не получилось

| Проблема | Что проверить |
| --- | --- |
| `no configuration file provided` | Выполните `cd ~/UknowApp` и повторите команду. |
| Docker сообщает об отсутствии прав | Проверьте, что вы вошли как `uknow` после добавления в группу docker. |
| Compose требует более новый Buildx | Обновите Compose и Buildx совместимыми пакетами из того же репозитория Docker. |
| Сборка мигает или строки накладываются | Проверьте `docker compose version`, `docker buildx version`, `echo "$TERM"` и `stty size`. Не удаляйте Docker или его данные. |
| Сайт не открывается или HTTPS не работает | Проверьте DNS, порты 80/443 и `docker compose logs --tail=100 frontend`. |
| Backend не становится healthy | Посмотрите `docker compose logs --tail=100 backend` и проверьте настройки `.env`. |
| Telegram не отвечает | Проверьте токен, `TELEGRAM_BOT_ENABLED`, подключение к Telegram и логи backend. |

При необходимости проверьте backend изнутри контейнера:

```bash
docker compose exec -T backend python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8000/api/health', timeout=5).read().decode())"
```

## Как сохранить данные школы

Если вы используете стандартную SQLite, откройте панель администратора → **«Дополнительно»**. Там можно скачать полный ZIP-архив и восстановить его.

Полный архив нужен для переноса школы на другой сервер: он включает базу, медиа и ключ Web Push, но не включает `.env`, токен Telegram или HTTPS-сертификаты. Настройки и секреты сохраните отдельно и храните всё в защищённом месте.

Не копируйте работающую SQLite-базу простым копированием одного `.db`-файла. Используйте встроенное резервное копирование. При PostgreSQL встроенные операции SQLite недоступны.

<details>
<summary>Как работает восстановление (подробнее)</summary>

В Docker база SQLite, медиафайлы и ключ Web Push находятся в постоянном томе `app_data`. В разделе **«Дополнительно»** администратор может скачать полную резервную копию и восстановить её. Архив содержит данные приложения, но **не содержит `.env`, токен бота и TLS-сертификаты**. Храните его в защищённом месте.

Для переноса всей школы используйте полный ZIP. Приложение проверяет контрольные суммы, целостность SQLite и доступность локальных вложений в учебных и личных чатах. Отдельную базу можно восстановить при наличии соответствующих файлов в каталоге медиа. При смене пути SQLite полный импорт размещает снимок по настройке нового сервера.

Оба вида восстановления применяются при запуске backend. В Docker перезапуск автоматический. Статус «восстановлено» появляется после миграций, проверки схемы и запуска служб приложения. При ошибке запуска или прерывании применения сервер возвращает предыдущие данные. Для переноса на другой сервер отдельно перенесите настройки окружения и учётные данные внешних сервисов.

Не копируйте работающую SQLite-базу простым копированием одного `.db`-файла: используйте встроенное резервное копирование.

</details>

<details>
<summary>PostgreSQL и миграции базы данных</summary>

### SQLite, PostgreSQL и миграции

По умолчанию UknowApp использует SQLite. В Docker том `app_data` сохраняется при пересборке.
Подключение выбирается через `DATABASE_URL`; бизнес-модели используют SQLAlchemy.
Существует опциональный сервис `postgres` (PostgreSQL 17), не открывающий внешний порт.

Для **нового пустого** развёртывания PostgreSQL задайте в `.env`:

```ini
COMPOSE_PROFILES=postgres
POSTGRES_DB=uknowapp
POSTGRES_USER=uknowapp
POSTGRES_PASSWORD=замените-на-надежный-пароль
DATABASE_URL=postgresql+psycopg://uknowapp:замените-на-надежный-пароль@postgres:5432/uknowapp
```

Пароль в URL должен быть URL-кодирован, если содержит специальные символы (`@`, `:`, `/`, `%` и др.).
Перед запуском приложения и **после проверки миграций** выполните:

```bash
docker compose --profile postgres up -d postgres
docker compose build backend
docker compose --profile postgres run --rm --no-deps backend alembic -c /app/alembic.ini upgrade head
docker compose up -d --build
```

Для существующей SQLite-инсталляции **не меняйте DATABASE_URL** без плана переноса данных.
Само изменение URL **не переносит** пользователей, переписки, медиа и другие записи.
Перед работой со схемой скачайте полную резервную копию, проверьте миграцию и её эффект на копии данных.

В проект добавлен Alembic для **ручного управления будущими миграциями**. `revision --autogenerate`
создаёт только черновик; запуск `upgrade head` требует отдельного решения.
Чтобы не ломать существующие установки, прежняя стартовая инициализация схемы пока сохранена
как переходная совместимость. Подробности и ограничения: [миграции и СУБД](docs/database-migrations.md).

Встроенные **полный ZIP** и **экспорт/импорт базы** предназначены только для SQLite.
Для PostgreSQL используйте `pg_dump` и `pg_restore`, а файлы медиа и ключ Web Push сохраняйте отдельно.
В админ-панели операции SQLite-бэкапа автоматически недоступны при подключении PostgreSQL.

</details>

<details>
<summary>Запуск для разработчиков на своём компьютере</summary>

Нужны Python 3.11+ и Node.js 22+. Выполняйте из корня проекта. При первом запуске создайте `.env` из шаблона и настройте пароль, Telegram и остальные параметры.

```bash
cp -n .env.example .env
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
python -m uvicorn app.main:app --app-dir backend --reload
```

В другом терминале, из корня проекта:

```bash
cd frontend
npm ci
npm run dev
```

Сайт: http://127.0.0.1:22222. Документация API: http://127.0.0.1:8000/docs.

</details>
